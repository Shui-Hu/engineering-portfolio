# 关键实现与取舍

## 模块分工

| 模块 | 职责 |
|---|---|
| session_manager.py | Tkinter 会话列表、消息预览、按钮状态、事件队列 |
| manager_core.py | 会话创建与接管、恢复流程、默认配置提交、连接生命周期 |
| bridge_runtime.py | iLink 登录、长轮询、附件收发、Codex 后端通信 |
| desktop_control.py | Windows 桌面本地接口发现、进程与能力检查、目标会话状态确认及归档请求 |

## 一键恢复：把多步交接放进一个入口

实际流程：停止微信连接 → 检查工作目录和配置 → 确认目标会话身份 → 判断占用状态 → 请求桌面端归档 → 确认归档及写入权释放 → 恢复原会话 → 接管成功后保存默认选择。

目标已经空闲时直接接管；已归档时直接恢复。正在运行或状态未知的桌面会话不发送归档请求。以下节选来自 desktop_control.py：

```python
def archive(self, thread_id):
        # Recheck identity and status immediately before mutating. A failed or
        # unknown result is never retried blindly by this client.
        self.check_idle(thread_id)
        return self._call('set_thread_archived', thread_id,
                          {'threadId': thread_id, 'hostId': 'local', 'source': 'codex', 'archived': True})
```

桌面接口发现时检查管道服务进程及能力；只有一个匹配接口才继续。归档请求超时后读取实际会话状态，不盲目重复归档。归档成功但接管失败时，保留原默认配置，并提示刷新重试。

这个功能依赖当前 Windows 桌面的内部本地工具接口，不能视为稳定公开 API。更新 Codex 后可能需要适配。为避免归档触发工作树清理，当前拒绝自动处理 Codex 托管工作树会话。桌面归档还可能影响该会话的派生子会话，需把这一变量纳入使用判断。

## 长轮询与停止流程

默认 45 秒是一次收消息请求的最大等待时间，服务端可以提前返回，并不是每隔 45 秒才检查一次。超时后可继续下一次请求；停止连接通过事件通知，已收到的批次尽量处理完再保存游标。

## 文件传输范围

附件按文件内容传输，不按扩展名筛选。代码默认本机向微信发送上限 80 MiB、入站下载载荷上限 100 MiB；服务端也可能有其他限制。传输 DWG、PLC 或单片机文件，不代表 AI 能直接理解或修改对应工程格式。
